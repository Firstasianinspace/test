# Решения и допущения

## Решения там, где ТЗ неоднозначно

- Роль хранится в `profiles.role` (не в JWT), пользователи не могут её менять.
- Статус меняется только через RPC `change_task_status`; у `authenticated` нет права UPDATE на колонку `status`; триггер перепроверяет переход (защита в глубину).
- Удаление задачи каскадно удаляет её историю (внутри БД); прямого DELETE по истории нет. Объект с задачами удалить нельзя (FK RESTRICT).
- Постановщик может править название/описание/объект/исполнителя в любом статусе (включая «Принята»); эти правки в историю не пишутся.
- Исполнитель при создании необязателен, но `Новая → В работе` невозможна без исполнителя.
- Любой постановщик работает с любой задачей; переходы исполнителя делает только назначенный исполнитель (постановщик — нет).
- Комментарий опционален, кроме `На доработке`.
- Исполнитель видит профили только связанных с его задачами людей (автор, авторы смен статуса).
- Стартовая страница: исполнитель → «Мои задачи», постановщик → «Объекты».

## Отклонения

- Функции-помощники в схеме `private` получают EXECUTE для `authenticated` — политики RLS выполняются с правами вызывающего.
- Навыки (skills) `supabase/agent-skills`, `anthropics/skills`, `shadcn-ui/ui` не установлены: установка стороннего кода была заблокирована политикой окружения.
- `CLAUDE.md` написан заново по плану (исходный вставленный текст правил недоступен).

## Не сделано / статус

- Облачный проект Supabase и деплой на Vercel не выполнены: нужны аккаунты владельца (шаги — в README, раздел «Облако и деплой»; `scripts/seed-cloud.ts` готов, но не запускался).
- Типы БД не генерируются через `supabase gen types`: строки таблиц валидируются zod-схемами на границе (`src/infrastructure/supabase/rows.ts`).
- RLS включён (`ENABLE`), но не `FORCE`: API-роли не являются владельцем таблиц, а `FORCE` рискует сломать функции SECURITY DEFINER.
- В `supabase/config.toml` провайдер email включён (`[auth.email] enabled`), а регистрация закрыта через `[auth] enable_signup = false`; это проверяется тестом.
- Лёгкий стек: локально Supabase запускается без Studio/Realtime/Storage (экономия памяти).
- Список «Мои объекты» исполнителя использует тот же экран объектов; RLS показывает только его объекты.
- Полный цикл с доработкой проверен автоматически в браузере (`e2e/cycle.spec.ts`) и в БД-тестах.

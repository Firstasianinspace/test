# Проверки безопасности

Автоматические тесты: `supabase/tests/security.test.ts` (`pnpm test:db`, против локального Supabase). Они ходят в PostgREST напрямую с anon-ключом и сессиями реальных пользователей — то есть в обход интерфейса.

| #   | Проверка                                                                                                  | Ожидаемый результат              |
| --- | --------------------------------------------------------------------------------------------------------- | -------------------------------- |
| 1   | Исполнитель читает чужие задачи / историю / объекты / профили                                             | пусто                            |
| 2   | Запрещённые переходы (new→accepted, same, чужой исполнитель, постановщик за исполнителя, без исполнителя) | ошибки CRT01/CRF01/CRN01/CRA01   |
| 2a  | Прямой UPDATE статуса                                                                                     | 42501 permission denied          |
| 3   | INSERT/UPDATE/DELETE по истории                                                                           | 42501                            |
| 4   | Анонимный доступ и регистрация                                                                            | пусто / ошибка                   |
| 5   | Исполнитель правит поля, создаёт, удаляет, меняет роль                                                    | 0 строк / ошибка                 |
| 6   | Доработка без комментария (пустой, из пробелов)                                                           | CRC01; полный цикл пишет историю |
| 7   | Не-исполнитель как исполнитель, подделка author/status, удаление объекта с задачами                       | CRV01 / 42501 / 23503            |

## Результаты последнего прогона

Прогон на локальном Supabase: `pnpm test:db` — **33 из 33 тестов пройдено** (в т.ч. проверка, что таблица переходов в TypeScript и в БД совпадает); `pnpm e2e` — **5 из 5** (в том числе полный цикл через интерфейс с доработкой и комментарием, 7 записей истории, недоступность чужой задачи по прямой ссылке) (включая прямую PATCH-атаку на статус из контекста браузера под сессией исполнителя: отклонена). После `pnpm build` строка `service_role` не встречается ни в `src`, ни в `dist`.

## Проверка облачного развёртывания (боевая база, снаружи, через публичный REST/Auth API)

- Регистрация: `disable_signup = true`, `POST /auth/v1/signup` → `422 signup_disabled`.
- Аноним (`apikey` без сессии): `tasks`, `objects`, `profiles`, `task_status_history` → `401`.
- Постановщик видит 7 задач и 3 объекта; Иван — 3 задачи и 2 объекта; Пётр — 3 и 2.
- Иван запрашивает задачу Петра по id → пустой ответ.
- Иван: прямой `PATCH status` → `403`; `INSERT` в историю → `403`; RPC `new → accepted` → `CRT01`.
- Постановщик: возврат на доработку без комментария → `CRC01`.
- Пётр вызывает RPC по задаче Ивана → `CRN01` (задача «не найдена»).
- Supabase Security Advisor: предупреждений об отсутствии RLS нет; остались два ожидаемых — RPC `change_task_status` вызываема авторизованными (так задумано, внутри проверяются роли) и выключенная защита от утёкших паролей.
